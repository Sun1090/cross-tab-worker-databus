## TypeScript 7：阻塞从「未知」变为「只剩上游」（Phase 329–332）

- TS 7.0.2 的 program 接口是**快照/句柄协议**，不是对象模型：`API` 持 `private client`、有 `fromLSPConnection`；节点是 `RemoteNode`（own keys `parent/view/index/_byteIndex/_sourceFile`）；`NodeHandle` = (path, node index) + `resolve()`。
- 覆盖：`unstable/ast` 11/17，加 `ast/factory`（`createSourceFile`）与 `ast/is`（9 个谓词）与 `unstable/sync`（`SymbolFlags`）。
- **没有文本→AST 解析器**：`factory.createSourceFile(statements, endOfFileToken, text, fileName, path)` 是节点工厂。基线的 `git show` 文本必须先落盘、用 `openFiles` 打开（inferred project）。
- **没有 `createProgram` / `ModuleResolutionKind`**：check 2 必须由生成的 tsconfig 驱动；`files` 用绝对路径可保住六个入口作为根（6 根 → 88 程序文件）。
- `forEachChild` 不是消失，而是挂在节点上（`RemoteNode.prototype.forEachChild`）。
- **别名解析是唯一真正的坑**：`Symbol.getExportSymbol()` 返回别名自身（flags 仍含 Alias）；`checker.getResolvedSymbol(identifier)` 在类型位置返回 `undefined`；**`checker.getDeclaredTypeOfSymbol(alias).getSymbol()` 才是目标**（flags=64，无 Alias）。
- 教训：两个后端在干净树上打印**同一行**毫无意义。必须造变异树做差分。该 bug 就是"干净树一致、变异树上 6 抓到 7 漏掉"。
- 现在的常驻保证：`pnpm verify:types:sensitivity` 在**两个** CI job 里跑（6.x 与 7.0.2），做泄漏/删除两种变异并要求各自失败；把别名解析改回 `getExportSymbol()` 会让它 exit 1。
- TS 7.0.2 **按平台分发**：需要 `@typescript/typescript-<platform>` 作为 `typescript` 的**兄弟目录**。CI 用 npm 在临时目录安装后只拷这两个目录；用 `npm pack` 解包会漏掉平台包（第一次 CI 就是这么红的）。本地沙箱曾用软链接掩盖它——Node 会先把软链接解析成 realpath 再找兄弟目录。
- 剩余阻塞只有 `typescript-eslint`（`8.72.1` 声明 `typescript: ">=4.8.4 <6.1.0"`，2026-10-31 复查仍是）。
