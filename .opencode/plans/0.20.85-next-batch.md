## Task 2 — e2e 韧化：owner 选举收敛前置（代码）

目标：给 owner 选举等待补统一收敛前置（cluster 恰好一个 owner 才发布），减少 `assignedCount` 单点翻转依赖。

问题来源：
- 测试大量用 `expect.poll(...filter(count===1).length).toBe(1)`，收敛后立刻做一次**无保护的二次读取**（如 `(await assignedCount(tabA)) === 1` 或 `indexOf(1)`）来定位 owner。demo 的 `#assignedCount` 由 1000ms setInterval 渲染，是**滞后快照**，两次读取之间 reconcile 可能翻转 → 偶发 `indexOf(1) === -1` 或 owner 判定错误。
- 需要：单一 helper 在**同一次观察**里既确认"恰好一个 owner"又捕获 owner 身份；且读取**实时 cluster snapshot** 而非 1s 滞后 DOM。

改动（仅 `e2e/demo.spec.ts`）：

1. 扩展 `declare global Window.__bus` 类型，加 `getClusterSnapshot: () => { assignedTopics: string[] }`。
2. 新增 helper（保留原 `assignedCount` 作为 DOM 兜底）：
   - `ownerCount(page)`：`page.evaluate(() => window.__bus?.getClusterSnapshot().assignedTopics.length ?? null)`，`null` 时回退 `#assignedCount`。
   - `waitForSingleOwner(tabs, { timeout = 30_000 })`：poll 直到 `counts.filter(c => c===1).length === 1`，在**同一轮** `findIndex(count === 1)` 捕获 owner 下标并返回；成功后再用 `expect(ownerIndex).toBeGreaterThan(-1)` 兜底断言。
3. 替换全部调用点（约 24 处）：
   - 收敛+定位一体：line 90-91、119-131、137-143、159-161、192-194、201-205、230-232、294、311-313、316-323、337-339、353-355、358、374-376、394-395、453、534 → `waitForSingleOwner(...)`（soak/migration 处保留 45_000 超时）。
   - 单 tab owner 等待：367、449、505、532、558 → `ownerCount(standby/page/tab)`（live 读取）。
4. 保留各测试原有注释语义；不改 demo.js、不改 SDK。

验证：

## 认证桥设计（已完成，2026-09-06）
